# 帳號與資料庫管理

這份說明怎麼在 Supabase 看使用者、開開發帳號和 Pro，以及資料庫裡各張表是做什麼的。

SQL 都在 Supabase 儀表板執行：選 HowWeiChi-app-JuanGo 專案 → 左邊 SQL Editor → New query → 貼上 → Run。如果跳出 Potential issue detected，按 Run query。

## 看是誰：「管理」裡的中文檢視表

左邊 Table Editor → 左上角的 schema 選單選「管理」，裡面的表欄位都是中文：

| 檢視表 | 內容 |
| --- | --- |
| 使用者 | ID、Email、暱稱、開發帳號、Pro 和到期日、程度測驗、本季積分和場數、最後備份、最後登入 |
| 對戰紀錄 | 每場對戰的雙方暱稱、分數、勝者和積分變化 |
| 單字回報 | 誰回報了哪個字、什麼問題 |
| 問題回報 | 開發帳號從 App 送出的問題 |
| 方案 | 兌換碼和活動送的 Pro |
| 課文書架 | 誰建了哪些書、幾課 |

這些只是給你看的。真正的表在 `public`，名稱和欄位還是英文，因為 App 是照這些名稱讀寫的；每張表和欄位都有中文說明，在 Table Editor 點欄位就看得到。「管理」裡的檢視表 App 和網站讀不到，裡面的 Email 不會外流。

**ID** 是每個人 10 碼的使用者 ID，也就是好友代碼，App 的「帳號」頁會顯示。請同學把 ID 傳給你，就能在「使用者」裡找到他：

```sql
select * from 管理.使用者 where "ID" = 'A1B2C3D4E5';
```

需要 `user_id`（一長串 uuid）的 SQL，都可以從這一列的最後一欄複製。

## 開發帳號

在 `dev_testers` 名單裡的帳號，登入後 App 會打開開發帳號：GOs PRO 的所有功能、開發者選項，以及「回報問題」。登出就恢復免費版。

加入（把 `她的user_id` 換成「使用者」裡的 user_id）：

```sql
insert into public.dev_testers (user_id, note) values ('她的user_id', '同學名字')
on conflict (user_id) do update set note = excluded.note;
```

移除：

```sql
delete from public.dev_testers where user_id = '她的user_id';
```

## 開 Pro

開三個月捲字 Pro（App 上的 Pro 和伺服器算的對戰場次都會打開）：

```sql
insert into public.entitlements (user_id, entitlement, source, status, expires_at)
values ('她的user_id', 'juango_pro', 'promo', 'active', now() + interval '3 months')
on conflict (user_id, entitlement) do update
  set status = 'active', expires_at = excluded.expires_at, updated_at = now();
```

- 延長：把 `'3 months'` 改成想要的長度再執行一次，會從執行當下重新算。
- 取消：

  ```sql
  update public.entitlements set status = 'expired', updated_at = now()
  where user_id = '她的user_id' and entitlement = 'juango_pro';
  ```

## 讓同學重新做 18 題程度測驗

```sql
update public.battle_players set retest = true where user_id = '她的user_id';
```

她下次進排位賽會先重做 18 題，這一季的積分從新的程度重新開始，場數和勝敗會留著。取消就把 `true` 改成 `false`。

程度測驗的結果存在伺服器（`battle_players.placed_level`）。換手機、重裝或登出再登入，App 會照伺服器的結果，不用重測，排位賽的積分也都還在。

## 資料庫檔案

`supabase/` 裡每個 `.sql` 檔都可以在 SQL Editor 整個重跑：

| 檔案 | 內容 |
| --- | --- |
| `account.sql` | `my_account()`：App 登入後拿 ID、開發帳號、程度測驗和 Pro 狀態 |
| `admin.sql` | 清掉沒在用的表和函式、「管理」中文檢視表、每張表和欄位的中文說明 |
| `battle*.sql` | 單字對戰、排位、好友、房間 |
| `subscriptions.sql` | 訂閱、衝刺包和 Pro 到期日 |
| `textbook.sql` | 課文書架 |
| `dev_builds.sql` | 開發帳號名單，以及舊的 Android 開發版（1.0.0）抓更新用的安裝檔 |
| 其他 | 雲端 AI 用量、單字回報、分享清單、活動 |

## 舊的 Android 開發版（1.0.0）

1.0.0 開發版不會讀 GitHub 上的 `release/latest.json`，而是向 Supabase 查 `dev_builds` 裡最新的一版。要讓它們收到更新，在 repo 根目錄：

1. `bash tools/release_link.sh build "這版改了什麼"`，把印出的第一段 SQL 貼去執行。
2. `bash tools/release_link.sh upload`，再把第二段 SQL 貼去執行。

安裝檔只有 arm64 版，而且要小於 50 MB（腳本會拿掉用不到的 CPU 架構）。更新到 0.2.0 build 11 以後，App 就改讀 `release/latest.json` 自己更新。
